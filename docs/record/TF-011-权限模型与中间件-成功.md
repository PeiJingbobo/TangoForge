# TF-011 权限模型与中间件 — 任务总结
> 结果：成功　|　日期：2026-08-06　|　执行人：ai

## 1. 任务范围
实现 `internal/auth` 权限模型：permissions 表（项目库）读写（全量覆盖语义）、权限中间件（ui 直接放行，其余查表未授权 403）、来源识别中间件 HTTP 层落地（TF-010 收口）；workdir 经 ctx 传递。

## 2. 交付内容
- **新增文件**：
  - `internal/auth/permission.go` — `PermissionStore`：`Get`（全量 16 项，缺失行 false）/ `Allowed`（行缺失/未知 action → denied 安全默认）/ `Set`（全量覆盖，事务 upsert，未知 action 拒绝 `ErrInvalidAction`）/ `Close`；连接缓存与 `task.Service` 分离
  - `internal/auth/middleware.go` — `IdentifyMiddleware`（识别 + 远程 401 + Actor 写 ctx）、`RequirePermission(action)`（ui 豁免 / 查表 / 403 + `OnDenied` 审计回调钩子）、`WithWorkdir`/`WorkdirFrom`（workdir ctx 传递）
  - `internal/auth/permission_test.go` — 16 用例
- **关键实现点**：
  1. **中间件顺序**（QA 确认）：workdir 写入 → 来源识别 → 权限判断 → handler（与 api 层 projectMiddleware 在前一致）
  2. **UI 不查权限表**：`actor_class=ui` 直接放行（专项用例：task.create 默认 denied 时 ui 仍通过）
  3. **denied 不阻断审计接入**：`OnDenied(ctx, workdir, action)` 回调由 api 层注入（TF-012 落地审计写库，auth 包不直接依赖 audit）
  4. **全量覆盖语义**：`Set` 未提交项重置 false；返回覆盖后全量（QA P3-5）
  5. workdir 经 `auth.WithWorkdir` 写 ctx（显式优于隐式），api 层 projectMiddleware 接入点已留
