# TF-032 项目设置页 — 任务总结

> 结果：成功　|　日期：2026-08-07　|　执行人：ai

## 1. 任务范围
项目设置页 `/project/:projectId/settings`（tab「设置」入口）：可视化编辑项目 `config.yaml`
（`state_machine` + `export` 两节），结构化表单 + YAML 原文兜底，显式保存。

## 2. QA 决策（用户确认）
| 决策点 | 结论 |
|---|---|
| 编辑形态 | 结构化表单 + YAML 原文兜底（高级区，兼顾未来字段扩展） |
| 保存方式 | 显式「保存修改 / 放弃修改」按钮（sticky 底部，QA-3） |
| 导出模板路径 | 展示 + 可编辑（相对项目目录；清空恢复默认） |
| 后端 | 新增 GET/PUT `/api/project-config`；读复用 `state_machine.read`，写仅 UI；审计 + WS 事件齐全 |

## 3. 交付内容
**后端（Go）**
- `internal/config/project.go`：新增 `UpdateProjectFile`（**部分更新**：yaml.Node 顶层 mapping 仅替换
  `state_machine` / `export` 两 key，**未知节原样保留**；缺失文件按默认创建）——与 `SaveProject`（全量替换）区分
- `internal/task/state_machine.go`：从 `UpdateStateMachine` 抽取 `ValidateStateMachineUpdate`
  （编辑校验 + STATUS_IN_USE 占用校验，不持久化），供 project-config 全量写入复用；
  `UpdateStateMachine` 持久化迁移到 `UpdateProjectFile`（全局单一写路径）
- `internal/api/handlers_project_config.go`：`GET /api/project-config`（state_machine.read）/
  `PUT /api/project-config`（仅 UI，handler 内二次校验 actor==ui）→ 校验 → 部分更新写盘 →
  审计 `project_config.updated` + WS `project_config.changed` → 返回落盘结果
- `internal/api/server.go`：主业务组注册路由；`task.Service` 接口补 `ValidateStateMachineUpdate`

**前端（React）**
- `types/models.ts`：`ProjectConfigDTO`（PascalCase 与 state-machine 端点一致）
- `hooks/useProjectConfig.ts`：GET/PUT hook（PUT 成功后同步失效 stateMachine/tasks 缓存）
- `features/settings/ProjectSettingsPage.tsx`：状态机编辑器（states 增删改 + 颜色取色器 +
  transitions from Select + to Badge 多选 + 恢复默认）+ 导出模板路径 + 高级 YAML 原文
  （表单/YAML 同 draft 双视图：表单编辑同步刷新 YAML，手动编辑 YAML 后保存以 YAML 为准，
  YAML 展示磁盘 snake_case 格式、解析兼容 PascalCase 键）；sticky 底部「保存修改/放弃修改」；
  校验失败（TASK_INVALID / STATUS_IN_USE）toast 并保留修改
- `components/project/project-panel.tsx`：PROJECT_TABS 尾部加「设置」tab（Settings 图标）
- `App.tsx` 路由 + `stores/project.ts` PROJECT_SECTIONS 同步 + `hooks/keys.ts` projectConfig key
- 新增依赖：`yaml@^2.9.0`（macOS 侧 pnpm 安装，npmmirror）
