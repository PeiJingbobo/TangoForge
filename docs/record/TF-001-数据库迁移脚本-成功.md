# TF-001 数据库迁移脚本 — 任务总结
> 结果：成功　|　日期：2026-08-05　|　执行人：ai

## 1. 任务范围
交付 `internal/db` 基础设施层：SQLite 连接管理 + 版本化迁移框架（up/down），按 QA Q4 双库模型落地全部 6 表 DDL 与索引，`CGO_ENABLED=0` 可编译。

## 2. 交付内容
- **新增文件**：
  - `internal/db/db.go` — Open（WAL + busy_timeout(5000) + MaxOpenConns(1)）、EnsureGlobal/EnsureProject（打开+迁移一步到位）、MetaDBPath/RegistryDBPath 路径工具
  - `internal/db/migrate.go` — Migration 结构 + schema_migrations 版本表 + Migrate/MigrateDown/CurrentVersion；GlobalMigrations（v1：projects 表）、ProjectMigrations（v1：tasks/permissions/import_drafts/skills/audit_log 5 表 + 3 索引）
  - `internal/db/migrate_test.go` — 11 个测试用例
- **关键实现点**：
  1. 双库模型：全局注册表库（registry.db，projects 表）与项目库（meta.db，5 表）分离，项目库不建跨库外键（应用层维护一致性）
  2. 迁移幂等：已应用版本跳过；每迁移独立事务，失败回滚且不记录版本
  3. MigrateDown 支持目标版本（0 = 全回退），目标版本不存在返回 ErrMigrationNotFound
  4. go.mod `go 1.22 → 1.25.0`（modernc.org/sqlite v1.56.0 硬性要求 Go ≥ 1.25）
