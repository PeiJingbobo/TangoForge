# PERT 任务依赖图重构方案

> 版本：v12.0（2026-08-18）
> 状态：优化完成，已通过自动化验证与用户验收
> 任务：文档编号 TF-055；TangoForge 实时任务板沿用 TF-028 跟踪本次返工

## 1. 问题与目标

旧实现使用矩形卡片、分散端口和密集交叉路径。第一轮重构仍存在正交折线、节点机械对齐、箭头不随视口缩放、边焦点框和状态角点等视觉问题。

本次目标：

- 使用圆形节点表达 PERT 事件/任务；
- 依赖方向固定为从左到右；
- 同一节点的所有出边共享右侧初始端点与短主干；
- 使用加粗三次贝塞尔曲线，并通过分层重排尽量减少交叉；
- 节点确定性散落分布，不形成机械网格；
- 每个根任务拥有独立线路色，后代出边继承同一谱系色；
- 连线可选中；选中后高亮两端、源端全部上游和目标端全部下游；
- 搜索任务时仅高亮命中节点的上游溯源和下游可达路径，并自动聚焦全部结果；
- 搜索命中节点使用与主体有间隙的同心圆标记；背景点击可清除路径高亮而保留标记；
- 空白画布可任意拖拽平移，滚轮缩放；
- 保留任务单击、双击、搜索、状态色和力导向兜底视图。

v12 在 Graphviz 交叉最小化结果之上增加二次曲线拟合：将安全路径采样为导向点，通过弦长参数化自然三次样条生成连续切线的贝塞尔段，并在每轮简化后重新做节点碰撞检测。层间净距扩大到 720px、行距扩大到 460px，节点加入确定性横向扰动，从而让平滑连接线优先获得更大的转弯空间。

## 3. 布局与布线

### 3.1 主布局：Graphviz dot + 障碍感知 B 样条

复杂依赖图优先按需加载 `@viz-js/viz` 的 Graphviz WASM，以 `dot` 完成 proper-layer 展开、层内交叉最小化、节点坐标和边路由。主要参数为：`rankdir=LR`、`splines=spline`、`remincross=true`、`mclimit=32`、520px 层间净距、1.6in 层内虚拟节点间距，以及 128pt 非连通分量间距。圆形节点固定为 64px，边统一从 `tailport=e` 进入 `headport=w`，因此同源边共享右侧初始端点。

Graphviz 的 `b` 绘制操作直接解析为一段或多段 SVG 三次贝塞尔，不再把折线控制点二次拟合；路径没有 `L` 折线段。`dot` 的样条路由把全部非端点节点作为障碍，真实 47 节点、134 依赖数据以曲线采样复核，连接线穿过非端点圆形节点为 0。

该真实依赖图经平面性检测为非平面图，因此在二维且每条依赖保持独立可选的前提下，无法保证所有边绝对零交叉。实现目标调整为：节点相交为硬约束；独立路径交叉使用 proper-layer + mincross 尽量降低。相同数据上，独立路径交叉对由自研兜底的 616 降为 424（约 31%）。非连通分量单独打包，避免彼此穿插。

Graphviz 模块由视图动态导入，WASM 下载/初始化或布局失败时立即保留同步的 TypeScript Sugiyama 布局，页面不会因增强引擎失败而空白。

### 3.2 同步语义与降级分层

仅消费 `GraphEdge.type === "dependency"`：

```text
layer(v) = 0                                      v 无前置
layer(v) = max(layer(predecessor)) + 1            其余节点
```

使用 Kahn 拓扑排序计算最长路径层；检测到环时显示错误提示并拒绝渲染脏图。

### 3.3 降级层内排序

每层执行 32 轮前向/后向 barycenter（中位数）扫描，按相邻节点的层内位置重排，降低层间交叉。排序后加入基于任务 ID 的确定性横向错位。节点层间净距增至 420px，行间净距增至 260px，圆心节距分别为 484px 与 324px；画布边距增至 180px，使节点不再挤在同一小片区域。

### 3.4 降级纵向坐标松弛

离散 barycenter 顺序完成后，再执行 18 轮父子坐标松弛：前向按父节点实际 y 中位数靠拢，反向按子节点实际 y 中位数回拉，同时允许层内节点依据目标 y 重新排序。每轮使用 PAVA 单调回归将期望坐标投影到“相邻圆心至少相隔 324px”的约束空间。最后以前驱坐标做一次前向收敛，使没有同层冲突的单前驱末端节点与父节点同高。

真实项目数据验证：旧布局中 TF-050 → TF-051 的纵向差约 854px；新布局为 0px，路径保持相邻层单段贝塞尔，不再斜跨 TF-030 等末层节点。

### 3.5 圆形节点

- 直径 64px；状态颜色作为填充和描边；
- 不显示额外状态指示点；
- 圆内显示任务编号，圆下显示截断标题；完整内容放入 SVG `<title>` 与 `aria-label`；
- 被选中边的两个端点增加主色外环；
- 上游/下游节点保持高对比，旁路节点降至 16% 透明度。

### 3.6 共享端点与贝塞尔路径

每条依赖从源节点右侧中心出发：

```text
源圆右锚点 → 共享第一控制点 → 目标侧控制点 → 目标圆左锚点
```

同源边的前两个路由点完全相同，因此共享初始端点与初始切线。路径使用 SVG 三次贝塞尔曲线。根任务谱系按黄金角生成稳定、不重复的色相；合流后的出边继承主上游谱系色。

主布局由 Graphviz 对节点障碍进行样条布线。以下候选曲线路由仅用于 Graphviz WASM 不可用时的同步降级：每个非端点节点建立“节点半径 + 32px”的排斥区，以每段 72 个采样点检测节点碰撞，并按跨度从短边到长边依次布线。

每条边同时生成四类三次贝塞尔候选：单段直接曲线、反解中点控制量得到的单段宽缓曲线、两段连续弧线、三段平滑走廊。候选高度来自端点中线、节点排斥区边界、等距曲率通道以及图形上下外侧通道。同源边固定共享第一控制点；单段曲线没有连接折点，多段兜底曲线在连接点两侧保持共线切线。

已选路径按 22px 间距采样到空间哈希网格。后续候选的评分依次考虑：节点碰撞（硬惩罚）→ 与既有路径的持续近距离重叠 → 绕行距离 → 曲线复杂度。轻微接近不再把路径无限推向外围，单段宽缓曲线获得显著优先级；只有发生节点碰撞或持续重合时才退化为两段/三段通道。共享源节点的短主干和共享目标附近允许自然汇聚，其余重叠路径自动选择不同高度和曲率。

布局边界使用曲线采样点而不是控制点计算，避免不可见控制柄制造大块空白并错误缩小“适应屏幕”。主布局保留 Graphviz 输出的稀疏坐标并置于无限画布，不再为塞进固定视口压缩节点间距。

## 4. 边选择与路径追踪

每条边渲染两层：

1. 可见路径：默认 2.5px、62% 透明度；
2. 命中路径：透明 16px stroke，支持鼠标和键盘选择。

选择边 `A → B` 后：

- 从 A 沿反向邻接表遍历，获得全部上游祖先；
- 从 B 沿正向邻接表遍历，获得全部下游可达任务；
- 只高亮实际遍历到的边，避免集合中偶然相连的旁路被误高亮；
- 选中边 4.5px、相关边 3.5px，保留谱系色，其余边降至 8%；
- 透明命中层禁用 SVG 焦点轮廓，不再显示矩形选中框；
- 箭头 marker 按 normal/active/dimmed 分离，填充透明度分别为 62%/100%/8%，不相关路径的箭头与线条同步降噪；
- 点击空白、再次点击所选边或“清除路径”按钮可退出选择态。

## 5. 搜索路径与结果聚焦

搜索输入经 300ms 防抖后同时驱动节点、依赖边和视口：

- 对每个命中节点沿反向邻接表追踪全部上游，沿正向邻接表追踪全部下游；
- 多个命中节点取各自实际遍历边的并集，不会因为后代合流而误吸附无关旁路；
- 相关边提升为 active 状态，无关边及其箭头同步降至 8% 透明度；
- 命中节点外侧绘制半径增加 11px 的主色同心圆，圆环与节点主体之间保留清晰间隙；
- 开始输入有效搜索词时清除旧的边选择，避免此前选中的路径污染搜索结果；
- 以全部命中节点的联合包围盒计算视口，预留圆形、标题和外部留白后自动居中；
- 单个结果最多放大到 1.65x；多个分散结果按联合边界缩小，确保全部进入可视区域；
- 无匹配结果时不强制移动视口，避免用户丢失当前观察位置。
- 点击画布背景只关闭搜索路径高亮与节点降噪，全图恢复正常对比度；搜索词和命中节点同心圆继续保留，便于在全图上下文中定位结果。

## 6. 无限画布

SVG 可视容器随窗口高度扩展（`100vh - 15rem`，最小 620px），逻辑图位于独立 `<g>`，不设置平移边界：

- 指针拖拽空白区域：任意平移；
- 滚轮/触控：0.04x–3x 缩放；
- 可见线条不使用 `non-scaling-stroke`，箭头采用 `userSpaceOnUse`，两者随画布同步缩放；
- 首次进入大图固定保持至少 0.58x 的可读尺度；超大图不再对准可能无节点的整图中心，而是锚定出边最多的主根任务，超出部分通过无限平移浏览；
- “适应屏幕”是显式全图概览操作，根据曲线真实 bounds 计算缩放和平移；
- 点阵 pattern 使用相同 zoom transform，平移和缩放时与逻辑画布同步移动；
- 不再依赖 `overflow:auto + viewBox` 裁切逻辑图。

## 7. 跨端边界

本次仅修改前端布局和渲染：

- HTTP `GET /api/graph` 不变；
- MCP `graph_get` 不变；
- CLI graph 输出不变；
- `GraphData` 数据契约不变；
- 原 D3 力导向视图继续作为可切换兜底。

父子层级与依赖关系使用同一套 DAG 布局。`parent` 边按“父 → 子”参与分层和路由；同一对任务同时存在父子与依赖关系时只绘制一条边，并优先保留依赖语义。纯层级项目因此也能形成从根任务向右展开的任务图。
