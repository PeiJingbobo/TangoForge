# 任务人工验证手册

本目录保存每个任务独立的人工验证手册。它回答“另一位操作者应如何验证这次任务”，不能只写实现摘要或一句“请检查功能正常”。

## 强制规则

1. 每个任务在实现交付时创建或更新一个手册，路径为 `<任务 ID>.md`，例如 `P5-03.md`。
2. 没有 backlog ID 的临时任务使用稳定、可识别的短名称，不能使用日期或操作者姓名代替任务名。
3. 手册必须包含范围、前置条件、测试环境、安全测试数据、编号步骤、预期结果、证据、清理/恢复和限制。
4. 每个步骤的执行状态必须是“通过、失败、未执行”之一，并记录日期；不得用“应该可以”。
5. 必需人工验证尚未执行时，backlog 状态保持 `待人工验收`。
6. 确实没有人工验证价值时仍创建手册，标记“不适用”，说明原因并列出替代自动化证据。
7. 环境暂不可用、没有测试主机或权限尚未授权，只能记为“未执行”，不能记为“不适用”。
8. 不记录真实端点、用户名、密码、证书内容、SSH 命令、Team ID、账号标识或机器专用路径。

## 手册与结果的关系

- 手册步骤应可重复使用；结果区记录本次实际执行状态。
- 自动化测试不能代替 GUI、Keychain 授权、Accessibility/Input Monitoring、Metal 呈现、全屏、物理键盘和真实 Windows 兼容验收。
- SSH 上的成功构建只可记录为命令行构建证据，不能记录为 GUI 人工验证通过。
- 失败时保留最小必要现象、脱敏证据和恢复方式，不粘贴秘密或完整用户数据。

## 新增手册

复制 [`template.md`](template.md) 的结构，以任务 ID 命名。任务交付报告必须给出手册路径和当前执行状态。
