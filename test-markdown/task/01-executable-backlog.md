# Farframe RDP 可执行任务清单

## 1. 字段说明

- **状态**：待办 / 进行中 / 阻塞 / 待人工验收 / 已完成。
- **依赖**：开始前必须完成的任务 ID。
- **验证**：完成任务必须留下的最小客观证据。
- **人工验收**：无法由命令行测试替代的真实环境检查。
- **人工验证手册**：每个任务对应 `manual-verification/<任务 ID>.md`；实现交付时必须存在并记录执行状态。

本清单中的任务按依赖顺序排列。每个任务应控制在一个可审查的纵向切片内；若实现范围明显过大，
使用 `task-template.md` 拆分，但不得把测试、失败路径或清理逻辑拆到“以后再做”。
必需人工验证未执行时，任务只能进入 `待人工验收`，不能进入 `已完成`。没有人工步骤时也必须
提供手册，明确“不适用”的理由和替代自动化证据。

## 15. 首个实施批次

首批只领取以下任务：

```text
P0-01 → P0-02
      ├→ P0-03
      ├→ P0-04
      └→ P0-05
上述全部完成 → P1-01
```

首批结束时应得到：

- 一个明确、干净的 Git 项目根目录；
- 已确认的平台、产品标识、持久化和架构决策；
- 安全的本地测试配置约定；
- 可由 Mac 命令行构建和测试的最小应用。
