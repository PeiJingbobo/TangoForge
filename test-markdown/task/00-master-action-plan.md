# Farframe RDP 主行动计划

## 1. 计划目的

本行动计划把 `Farframe-RDP-Development-Plan.md` 转换为可按依赖执行、可验证、可交接的工程任务。
目标不是同时铺开所有模块，而是逐步形成可运行的纵向闭环：

```text
工程可构建
→ Bridge 可创建和释放会话
→ 可安全连接和断开
→ 可显示
→ 可输入
→ 可控快捷键
→ 可保存配置并一键连接
→ 基础通道
→ 高级能力
→ 安全、稳定性和发布验收
```

## 2. 执行原则

### 2.1 每个任务必须形成闭环

每个任务至少包含：

- 明确的用户行为或工程能力；
- 正常路径、失败路径和取消/清理路径；
- 与风险相称的自动化测试；
- 可重复执行的构建或测试命令；
- 必须在 Mac 或 Windows 图形环境中完成的人工验收；
- 位于 `docs/task/manual-verification/<任务 ID>.md`、可交给另一位操作者执行的人工验证手册；
- 对兼容性矩阵、许可证或架构文档的必要更新。

### 2.2 固定的技术边界

- SwiftUI：应用外壳、连接列表、表单、设置和导航。
- AppKit：远程窗口、第一响应者、菜单快捷键、窗口和焦点生命周期。
- C/Objective-C++ Bridge：拥有全部 FreeRDP/WinPR 指针，对 Swift 暴露不透明句柄。
- Metal/`CAMetalLayer`：脏矩形渲染。
- Security.framework：Keychain 密码存储。
- SwiftData 或 SQLite：非秘密配置，必须先通过决策任务确定其一。
- OSLog：隐私标注和脱敏诊断。
- Xcode：应用构建；CMake/Ninja：锁定版本的原生依赖构建。

### 2.3 全程不允许破坏的约束

- UI 状态只在 `@MainActor` 更新；协议循环和阻塞 Keychain 操作不占用主线程。
- 每个会话有唯一 ID，迟到回调不能污染新会话。
- 断开、取消、失焦、应用退后台和窗口关闭都必须释放按键、鼠标按钮、通道和事件捕获。
- 不为通过测试而降低 TLS/NLA、静默接受证书或修改签名/权限模型。
- 密码、可复用令牌、哈希和私钥不得进入数据库、UserDefaults、日志、截图、命令参数或测试夹具。
- 所有服务端字节、尺寸、路径、帧和回调均按不可信输入处理。

## 3. 阶段与里程碑

## Phase 0：仓库与关键决策基线

**目标**：把当前“只有计划文档”的目录变成可开始编码、可复现验证的项目根目录。

**必须完成**

- 初始化版本控制基线、忽略规则和仓库 README。
- 记录并确认最低 macOS、Bundle ID、Keychain service、数据持久化方案。
- 固定首个支持架构为 Apple Silicon arm64；是否同时支持 x86_64/Universal 单独决策。
- 建立架构决策记录（ADR）、第三方许可证目录和兼容性矩阵骨架。
- 定义本地机密配置方式，确保真实端点和凭据不被跟踪。
- 在 Mac 上探测 Xcode、SDK、架构和可用 destination；不先验假设工程名或 scheme。

**退出门槛**

- 所有关键决策均有理由、影响和回退方案。
- 仓库不包含机器信息、凭据、签名身份或生成产物。
- 后续任务能引用稳定的项目标识、平台下限和目录结构。

## Phase 1：可复现的 macOS 应用骨架

**对应源计划**：步骤一。

**纵向切片**

1. 创建 SwiftUI macOS App，并能从应用外壳打开设置窗口。
2. 由 SwiftUI 创建 AppKit 远程会话窗口和空白 `RemoteCanvasView`。
3. 建立模块边界、统一错误模型和 App/Session/Input/Render/Security/Channel 日志分类。
4. 建立 Debug、Release、Sanitizer 配置和最小单元测试 Target。

**退出门槛**

- 干净环境可依 README 构建。
- Debug 与 Release 均能构建，应用可启动并打开设置和空远程窗口。
- 代码无新增警告；Derived Data 使用明确的 Git 忽略目录。
- Personal Team 或 `Sign to Run Locally` 下标识保持稳定，但不得为绕过问题改 Bundle ID 或权限。

## Phase 2：FreeRDP 依赖与窄 Bridge

**对应源计划**：步骤二。

**纵向切片**

1. 调研并锁定 FreeRDP 3.x 精确版本/提交及依赖能力集。
2. 用 CMake/Ninja 为 arm64 构建最小客户端静态产物。
3. 产出确定性构建脚本或 XCFramework，移除 Homebrew 运行时依赖。
4. 建立只暴露 Farframe API 的 Bridge。
5. 实现会话句柄创建/销毁、版本读取、错误与事件回调。
6. 生成实际链接组件及许可证清单。

**退出门槛**

- Xcode 只依赖 Farframe Bridge，不在 Swift 中散布 FreeRDP 结构体或头文件。
- Bridge 明确记录指针所有权、线程、空值、取消与回调生命周期。
- 会话反复创建和销毁无崩溃、泄漏或重复释放。
- Release 产物不包含意外绝对动态库路径；没有 Homebrew FreeRDP 也能构建和运行打包产物。

## Phase 3：最小安全连接闭环

**对应源计划**：步骤三。

**纵向切片**

1. 实现可测试的会话状态机和唯一 session ID。
2. 映射主机、端口、用户名、域和临时密码到 Bridge settings。
3. 实现 DNS/TCP/TLS/NLA/CredSSP 连接流程。
4. 实现首次证书、仅本次信任、记住指纹和证书变化决策。
5. 将网络、TLS、证书、认证、服务端拒绝和协议错误映射为不同用户错误。
6. 实现连接取消、主动断开和所有资源清理。

**退出门槛**

- Windows 11 Pro 与至少一个当前 Windows Server 可登录并安全断开。
- 错误密码只失败一次，不触发无界重试。
- 不存在主机、端口关闭、证书变化与 NLA 失败可区分。
- 连接取消和断开不遗留线程、socket、context 或旧会话 UI 回调。

## Phase 4：远程画面闭环

**对应源计划**：步骤四。

**纵向切片**

1. 接收桌面尺寸、帧和脏矩形回调，并做边界检查。
2. 建立线程安全帧缓冲和有界脏矩形队列。
3. 将 BGRA 更新上传到 Metal 纹理并显示。
4. 实现窗口适配、原始像素、Retina、全屏和动态分辨率。
5. 实现远程光标形状、热点和可见性。
6. 保留仅用于诊断的 Core Graphics 回退路径。

**退出门槛**

- 桌面颜色、方向、尺寸和光标热点正确。
- 协议线程、渲染和主线程职责分离；画面更新不饿死输入。
- 快速变化、窗口缩放、全屏切换和显示器切换无越界、旧帧覆盖或持续内存增长。

## Phase 5：基础键鼠与输入法

**对应源计划**：步骤五。

**纵向切片**

1. 让远程画布成为第一响应者并建立焦点生命周期。
2. 实现鼠标移动、按键、滚轮和扩展按钮的坐标转换。
3. 建立 macOS `keyCode` 到 Windows scan code 的确定映射。
4. 忽略 macOS 本地 IME 文本，只发送物理 scan code，由受控端输入法处理。
5. 实现左右修饰键、锁定键、功能键和按键重复。
6. 建立按下状态注册表，在所有退出路径合成 key-up/button-up。

**退出门槛**

- 基础按键、导航键、F1–F12、鼠标和滚轮通过测试。
- macOS 使用中文输入源时仍可向受控端发送字符键和 Backspace scan code。
- 窗口失焦、应用切换和突然断线均无卡住的 Ctrl/Alt/Windows 键或鼠标按钮。
- 窗口、全屏和 Retina 下鼠标坐标准确。

## Phase 6A：应用内快捷键捕获

**对应源计划**：步骤六的应用内捕获部分。

**纵向切片**

1. 建立 `ShortcutPolicy` 数据模型与默认语义映射。
2. 在物理修饰键映射前执行语义快捷键覆盖。
3. 通过 responder chain、`performKeyEquivalent` 和 local monitor 处理应用内捕获。
4. 实现不可关闭的紧急释放组合。
5. 实现捕获状态指示和焦点/断开后的恢复。

**退出门槛**

- 启用时 `Command-W` 不关闭 Farframe，并向 Windows 发送配置的 `Ctrl-W`。
- 禁用或画布未聚焦时，`Command-W` 恢复正常 macOS 行为。
- 常用预置快捷键按配置只到达远端，本地菜单不执行。
- 每条输入路径都有成对的 down/up；安全释放组合始终有效。

## Phase 7：Profile、Keychain 与一键连接

**对应源计划**：步骤七。

**纵向切片**

1. 实现不含秘密的 `ConnectionProfile` 存储和校验。
2. 用稳定 Profile UUID 建立异步 Keychain CRUD。
3. 分离“保存密码”和“信任证书”的用户决策。
4. 实现首次成功后保存、重启后单击卡片直接连接。
5. 实现更新/删除密码、删除连接及信任记录的部分失败恢复。
6. 实现可关闭的端口/网关可达性提示，不用探测结果阻止真实连接。

**退出门槛**

- 应用重启后可用 Keychain 凭据一键进入连接流程。
- 数据库、偏好、日志和诊断中找不到密码或可复用秘密。
- Keychain 锁定、拒绝、缺失、重复、更新和删除失败都有安全处理。
- 删除 Profile 后凭据和 Profile 级信任记录被删除，或明确报告可重试的部分失败。

## Phase 8：基础 RDP 通道

**对应源计划**：步骤八。

**执行顺序**

1. 动态分辨率（若 Phase 4 尚未完成完整能力）。
2. 纯文本剪贴板双向同步和会话级开关。
3. 远端音频输出与设备释放。
4. 用户明确授权的单目录重定向。
5. 时区、键盘布局和锁定键同步。
6. 在边界、格式白名单与取消模型成熟后，再评估图片/文件剪贴板。

**退出门槛**

- 每个通道有独立最小权限开关，关闭后双向均停止。
- 大数据传输可取消且 UI 不冻结。
- 断开后音频、剪贴板和目录句柄完整释放。
- Windows 只能看到用户明确授权的目录。

## Phase 6B：增强系统快捷键捕获

**对应源计划**：步骤六的增强捕获部分。

**前置条件**：Phase 5、Phase 6A 已稳定；输入状态注册表和生命周期清理已有测试。

**纵向切片**

1. 实现辅助功能/输入监控权限状态和安全降级 UI。
2. 仅在应用前台、会话已连接、画布为第一响应者且用户启用时安装 active `CGEventTap`。
3. 处理 event tap 超时禁用、恢复和降级。
4. 验证 `Command-Tab`、`Command-Space`、Control-方向键等候选组合并如实记录限制。

**退出门槛**

- 权限拒绝不影响应用内捕获和基本会话。
- 失焦、退后台、断开和窗口关闭后 event tap 必定移除。
- 不拦截锁屏、强制退出等安全路径。
- 无法抑制的系统保留组合已在 UI 和兼容性矩阵中披露。

## Phase 9：高级 RDP 能力

**对应源计划**：步骤九。

每个能力必须是独立任务、独立开关和独立测试环境，不并行铺设未验证骨架：

1. RD Gateway。
2. 多显示器。
3. RemoteApp。
4. 麦克风重定向。
5. 有限、可取消、可观察的自动重连。
6. 打印机、智能卡等仅在有明确需求和测试环境时立项。

**退出门槛**

- 每项能力有明确的“支持/部分支持/实验性/不支持”记录。
- 网关、目标认证和直连错误可区分。
- 旧会话、旧输入状态和旧窗口不会因重连或 RemoteApp 生命周期而复活。
- 权限拒绝只关闭对应设备能力，不影响桌面连接。

## Phase 10：安全加固

**对应源计划**：步骤十。

**必须完成**

- 威胁模型覆盖凭据、中间人、恶意服务端、剪贴板、文件名/路径、日志、依赖和事件捕获。
- 对跨 Bridge 的尺寸、长度、像素、剪贴板和路径做上限与溢出检查。
- 阻止路径穿越与符号链接越权。
- 建立 SBOM/组件清单、许可证和 CVE 更新流程。
- 检查诊断包与崩溃上下文的秘密泄漏。
- 实现可验证的“清除全部本地数据和凭据”。
- 验证 Hardened Runtime 兼容性，不以关闭安全能力作为修复。

**退出门槛**

- 畸形输入、异常证书、超大剪贴板和路径攻击测试通过。
- ASan/UBSan/TSan 的适用套件无已知越界、UAF 或数据竞争。
- 清除操作后数据库、Keychain 和证书信任均无残留。
- 增强捕获在 Farframe 失焦时绝不运行。

## Phase 11：稳定性、性能、可访问性与发布

**对应源计划**：步骤十一、兼容性矩阵、发布门槛和最终完成定义。

**必须完成**

- 反复连接/断开、长连接、睡眠唤醒、切网、丢包、服务端重启。
- 主线程、协议线程、渲染线程、内存和 GPU 基准与回归阈值。
- 脏矩形合并、有界队列和过时帧丢弃；输入优先于非关键刷新。
- 错误恢复动作与可导出的脱敏诊断包。
- VoiceOver、键盘导航、对比度和缩放。
- 完整兼容性矩阵和已知限制。

**发布门槛**

- 连接、认证、断开和重连没有已知高危崩溃。
- 密码只存 Keychain；证书不会被静默接受。
- 启用的快捷键只在远程焦点内生效，离开焦点后 macOS 行为立即恢复。
- 无卡住修饰键或后台 event tap。
- 第三方许可证完整，兼容性声明与实测一致。
- 用户可删除连接及其全部凭据。

## 4. 依赖关系与并行边界

```text
P0 → P1 → P2 → P3 → P4 → P5 → P6A → P7 → P8 → P6B → P9 → P10 → P11
```

允许的有限并行：

- Phase 1 后可并行准备测试基础设施和兼容性矩阵，但不能伪造测试结果。
- Phase 3 后可设计 Profile UI，但 Keychain 一键连接必须等待认证和证书失败处理稳定。
- Phase 4 后可准备渲染性能夹具；Phase 5 前不得实现快捷键策略。
- 基础通道可逐项交付，但不得在连接、输入和清理尚未稳定时同时开发全部通道。
- 安全工作贯穿所有阶段；Phase 10 是集中审计与攻击性验证，不是首次考虑安全。

## 5. 验证策略

每个阶段按以下顺序执行，前一级失败时先修复再扩大范围：

1. 纯单元测试：状态机、映射、几何、Profile 校验、信任策略、错误映射、脱敏。
2. 集成测试：Bridge 所有权、设置映射、取消、回调、Keychain CRUD、畸形输入。
3. 确定性的 UI 测试。
4. Mac 命令行构建和测试。
5. 解锁图形会话中的 GUI、Keychain、权限、Metal、全屏和物理键盘人工验收。
6. 真实 Windows/Windows Server、网络故障和 RDP 通道兼容验收。

每个任务在实现交付时都必须新增或更新独立的人工验证手册。手册描述“如何验证”，并记录当前
“已通过、失败或未执行”的状态。没有合理人工步骤时仍需保留手册，标记“不适用”并链接替代的
自动化证据。环境暂不可用不等于“不适用”，此时任务状态保持 `待人工验收`。

远程 Mac 验证时，必须先探测真实 `.xcodeproj`/`.xcworkspace`、scheme、SDK、架构和
destination，再构造命令。成功的 SSH 构建只证明命令行构建通过，不代表 GUI 或权限验收通过。

## 6. 每次交付的报告格式

每个任务交付至少报告：

- 完成的行为和失败/取消路径；
- 实际执行的命令；
- 通过的测试及数量；
- 未运行的测试与具体原因；
- 仍需人工执行的 Mac/Windows 验收；
- 对应人工验证手册的路径及执行状态；
- 残余风险和已知兼容限制；
- 是否触及凭据、证书、输入捕获、原生内存或第三方依赖。

## 7. 当前起点与下一步

截至本计划创建时，项目根目录只有 `AGENTS.md` 和开发计划文档，未发现 Git 仓库或工程代码。
因此第一个实施批次应严格按以下顺序执行：

1. `P0-01` 仓库基线；
2. `P0-02` 平台与产品标识决策；
3. `P0-03` 技术和数据决策；
4. `P0-04` 安全的本地配置与文档骨架；
5. `P1-01` 最小 Xcode 应用。

在这些任务完成前，不开始 FreeRDP、快捷键捕获或虚拟通道实现。
